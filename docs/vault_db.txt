PROJECT 6: VaultDB
"Track Who Accessed Your Data (GDPR/HIPAA Compliance)"
 Project Type: Audit Logging & Access Control Tool



🎯 WHAT IS THIS PROJECT?
You will build a tool that:
Logs every database query (who, what, when)
Stores logs in immutable way (can't delete history)
Controls who can access which tables
Shows audit dashboard (see who accessed what)
Exports reports for compliance (GDPR, HIPAA, PCI)
Real Example:
Compliance officer asks: "Who accessed customer #123's data last month?"
Without audit tool: Shrug 😅
With VaultDB:
Dashboard query: SELECT * FROM audit_log WHERE customer_id=123

Results:
2024-01-15 10:30  | John Smith   | SELECT email FROM customers WHERE id=123
2024-01-20 14:45  | Sarah Jones  | SELECT * FROM customer_orders WHERE customer_id=123

Report: "John and Sarah accessed this customer 2 times total"
Compliance: "Great! Here's your audit trail for regulators" ✅


V1 SCOPE: WHAT YOU MUST BUILD (3 MONTHS)
✅ Requirements: What's Expected
You need to build a middleware + dashboard that logs all queries and controls access.
Core Features (must have):
1. Query Logging Middleware
Intercept all SQL queries
Store: WHO (user), WHAT (query), WHEN (timestamp)
Store in immutable log (database, not editable)
Don't slow down queries
2. Immutable Audit Log
Once written, can't be deleted
Can't be modified (not even by admin)
Timestamp can't be changed
Cryptographic signature (optional but great)
Example log entry:
{
  "timestamp": "2024-01-15T10:30:45Z",
  "user": "john@company.com",
  "query": "SELECT email FROM users WHERE id = 123",
  "result": "1 row returned",
  "database": "production_db",
  "table_accessed": "users"
}

3. Simple Access Control
3 roles: admin, writer, reader
admin: can read/write/delete from any table
writer: can read + write from assigned tables
reader: can only read from assigned tables
Example:
John (admin): full access
Sarah (writer): can modify customer + orders tables
Bob (reader): can only see reports table
4. Audit Dashboard
Web page showing all queries
Filter by user (show Sarah's queries)
Filter by table (show all queries to users table)
Filter by date range (last 7 days)
Sort by newest first
Color code: sensitive queries in red
5. Sensitive Query Detection
Flag certain queries as sensitive
Examples: queries accessing password, credit_card, SSN columns
Alert: "Sensitive query detected!"
Store in special log
6. Export Reports
Export audit trail to PDF
Example: "All queries to customers table in January"
For compliance officers to give to regulators
Include: user, query, timestamp, table affected
7. Testing
Test on PostgreSQL
Test with 1000+ queries
Test all access control scenarios
Test sensitive query detection
